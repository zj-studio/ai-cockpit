# 生产任务异常卡点与统一视图增补设计

**编制**：砚舟（Codex）  
**日期**：2026-09-12  
**依据**：老板生产任务异常卡点需求、v0.4 两套独立后台定调  
**状态**：原型待老板审批  
**边界**：只读聚合，不写、不派单、不通凭据

---

## 1. 定位

在统一只读视图中增加“生产任务”视图，作为以下两部分的共同落地：

- 老板生产任务异常卡点需求。
- 压测台账 003 六站流程真实数据改造。

原则：

1. 正常任务看状态链和进度。
2. 异常任务看卡点、原因、责任和处置。
3. 阻塞、失败、红线异常强提醒。
4. 页面只显示，不执行审批、不派单、不改状态。

---

## 2. 正常任务状态链

```text
待派单
  -> 已派单（必须带真实任务号）
  -> 员工执行中
  -> 已交稿
  -> 验收中
  -> 完成
```

打回：

```text
验收中 -> 打回（记录打回次数） -> 员工执行中 -> 已交稿 -> 验收中
```

要求：

- 没有真实任务号，不得显示为“已派单”。
- 打回次数必须可见。
- 超过阈值自动升级为异常。

---

## 3. 异常类型

| 编号 | 异常类型 | 典型触发 |
|---|---|---|
| E1 | 模型自产未派单 | 小墨直接输出成稿，无 dispatch、无任务号 |
| E2 | 通道不通 | relay / dispatch / executor 不可用或被拒 |
| E3 | 岗位路由不命中 | 目标岗位名称无法匹配员工应用 |
| E4 | 超时 | 员工未接单或执行超时 |
| E5 | 执行报错 | 沙箱、出网、工具、模型或脚本失败 |
| E6 | 验收打回 | 验收不通过，打回次数达到阈值 |
| E7 | 会话或上下文异常 | 多轮丢上下文、无法引用上一轮内容 |

---

## 4. 每条异常卡片字段

1. 任务号，缺失时显示“无任务号”。
2. 客户或需求来源。
3. 目标岗位。
4. 当前卡住环节。
5. 原因分类。
6. 发生时间。
7. 责任处理人。
8. 处置状态。
9. 关联证据或回执。

处置状态：

```text
待处理 / 处理中 / 已修复待复测 / 已关闭
```

---

## 5. 界面结构

### 顶部

- 标题：生产任务 · 异常卡点。
- 数据模式：样例数据 / 真实只读数据。
- 数据来源标识：Dify 内 / 外部协同。

### 指标

- 任务总数。
- 正常运行。
- 异常任务。
- 红线或阻塞。
- 待处理。

### 筛选

- 所属系统。
- 正常 / 异常。
- 异常类型。
- 责任处理人。
- 处置状态。

### 异常区

异常任务置顶，使用红色或橙色高亮。

每条显示：

```text
任务号 | 目标岗 | 卡住环节 | 原因分类 | 时间 | 责任人 | 处置状态 | 证据
```

### 正常任务区

每条显示六段状态链：

```text
待派单 -> 已派单 -> 执行中 -> 交稿 -> 验收 -> 完成
```

当前节点高亮，打回次数显示在验收节点旁。

### 详情侧栏

点击任务后只读查看：

- 任务摘要。
- 时间线。
- 责任链。
- 证据和回执。
- 所在原系统。

只提供“查看原系统”链接，不提供审批、派单、驳回按钮。

---

## 6. 提醒策略

强提醒：

- 红线。
- 阻塞。
- 失败。
- 执行超时。
- 会话异常。
- 打回超限。

摘要提醒：

- 普通异常聚合。

静默：

- 正常状态推进。

---

## 7. 数据来源

### Dify 内

- 由现有驾驶舱 / Dify 数据源提供。
- 任务号、派单、执行、交稿和验收状态。
- 不新增 Dify Adapter。
- 不写 Dify。

### Dify 外

- 由外部协同控制面提供只读 Snapshot。
- 包含任务、进度、阻塞、风险、产物、待审批和审计摘要。
- 只使用 `/readonly/v1/snapshot`。
- 不提供写接口。

---

## 8. 入口

统一视图推荐入口 A：

```text
工作总览 / 协同看板
  ├─ Dify 员工组
  ├─ 外部协同组
  └─ 生产任务 · 异常卡点
```

生产任务页可作为统一视图中的独立子页，不修改现有生产任务页，只新增只读页面。
