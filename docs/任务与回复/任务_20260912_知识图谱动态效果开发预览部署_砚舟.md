## 三、执行步骤

### 1. 只读定位

确认并记录：

1. 开发预览宿主目录中的 `galaxy3d.js` 路径。
2. nginx 容器内对应的实际文件路径。
3. 页面实际读取的是哪一个路径，是否是挂载或需 `docker cp` 同步。
4. 当前旧文件的字节数和 SHA256。

不得根据旧材料直接假定路径。

### 2. 新文件校验

1. 从老板本机取得 `G:\Codex\01_项目\galaxy3d.js`。
2. 校验为 `44626` 字节。
3. 校验 SHA256 为 `a1bfff80ddf8f26db1eb6f43e61c63ab7bcdabc76d699c437eaa0a62eeb70897`。
4. 在服务器执行 `node --check galaxy3d.js`，必须通过。

### 3. 备份

1. 对宿主文件和 nginx 容器内文件分别备份。
2. 备份名包含时间戳和任务编号。
3. 记录备份路径、字节数和 SHA256。
4. 确认备份可读，并准备回滚命令。

### 4. 替换

1. 先更新宿主源文件，再同步到 nginx 容器。
2. 使用原子替换或明确的同步方式。
3. 不新增端口、不修改 nginx location、不动 Basic Auth 配置。

### 5. 部署后核验

1. 宿主文件 SHA256 等于 `a1bfff80…`，字节数等于 `44626`。
2. nginx 容器内文件 SHA256 等于 `a1bfff80…`，字节数等于 `44626`。
3. 从页面实际请求路径抓取资源，确认返回新版内容，不能只看宿主文件。
4. 页面地址可访问且无白屏。
5. 截图或录屏覆盖桌面端和手机端。

建议核验地址：

```text
http://150.158.115.88/cockpit-v070_dev/#/graph
```

若实际地址或容器资源路径不同，以现场拓扑为准并回报真实地址。

任一情况出现时立即停止并回报：

1. 新文件字节数或 SHA256 不符。
2. `node --check` 不通过。
3. 旧文件无法可靠备份。
4. 宿主和 nginx 容器路径无法确认。
5. 部署后页面异常或控制台出现致命错误。
6. 需要改 nginx 配置或使用高权凭据。

不得自行扩大范围、自行改生产或改用未经批准的执行通道。
